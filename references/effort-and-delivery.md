# 工时、作品组合与交付边界

## 先固定估计对象

为每项候选记录核心范围版本、已有资产与工具、个人经验、目标环境和依赖。评分、估时与验收必须指向同一版本；不能用扩展版的技术上限评分，再用最简小样的工时承诺交付。

核心要包含可观看的美术完成度。可另估“验证小样”，但不能将小样完成等同于作品完成。尚未检查的资产可用性、课程工程和软件兼容性写为假设。

## 用工作包估小时

| 工作包 | 包含内容 | 容易漏掉的成本 |
|---|---|---|
| 学习与关键验证 | 必要教程、接口试验、路线筛选 | 学会模块不等于完成整合 |
| 资产与数据 | 制作或生成、遮罩、绑定、导出、资源整理 | 外部资源的改造与替代 |
| 引擎整合 | 材质、粒子、状态、交互、数据消费 | 模块接口和版本差异 |
| 美术迭代 | 主形、节奏、色值、材质、受光、镜头 | 将全部打磨错误归为可选扩展 |
| 验证与交付 | 代表输入、异常、录制、文档、贡献说明 | 最终包装与修复 |
| 特定返工 | 明确未知导致的重做或备选路线 | 与正常美术迭代重复计时 |

各工作包分别给低、高估计，再汇总。没有个人历史数据时称“判断性规划范围”，不称行业平均、置信区间或保证上限。难度不能直接换算工期，也不要无理由统一添加某个百分比的风险余量。

分别记录人工有效时数、机器缓存/渲染等待、日历跨度。只有具备实际条件的等待才能与其他任务重叠；不要默认所有步骤可并行。共享资产成本只算一次，同时记录共享依赖失效可能拖延多项作品。

## 容量与取舍

可用容量是各可工作日期的有效时数之和，扣除已知不可用时段。日投入增加只改变容量，不自动减少任务工作量。总小时看似够，也要检查先后依赖、失败返工与最终包装时间。

比较预算时说明：完整核心的估计范围、可用容量、必做项、缺口及最早复核点。接近估计低端不能解释为稳妥交付；更不能用排满日历遮住不足。

不足时提出具体建议：延后部分交付、减少输入/变体范围、复用已验证资源或调整顺序。删去原本就不在核心的扩展，不算缩短核心工期。会改变已确认需求的简化应明确提出，不能写成用户已经接受。

## 选组合，不只选最高分

比较各项主要证明的能力：效果设计、材质与表示、程序化资产、实时交互、美术工具、资源取舍。检查多个项目是否重复证明同一种能力，以及各自是否有可交付的个人贡献。

组合还受必保留项、总工时、依赖关系和能力缺口影响。高分项可能同质，或共同依赖尚未验证的技术；说明推荐组合的取舍，不直接取总分前三，也不为迎合偏好改分。

保留已确定的候选 ID、集合与制作顺序。撤回项标为历史，不让旧文档或旧 clip 覆盖最新决定。

## 先验证最可能推翻计划的环节

优先建立最小端到端闭环，再扩展外观和输入。每项验证写清环境、输入、预期、观测方式，以及失败后如何改变路线或估时。小样只验证声明覆盖的部分，不自动升级为完整工程成熟。

可按核心选择验收例子：局部破坏验证新洞口可通行且残墙仍阻挡；路径生成验证曲线改变后形态与生成顺序；角色表面效果验证运动中的附着和遮挡；烘焙流体或生长验证数据导出、目标引擎播放、可控范围及资源代价。不是每个 Demo 都必须具备这些能力。

记录首个关键验证的实际投入，更新后续工作包；不要等到截止前才发现管线不可用。验证失败后优先定位问题，更多网页不能替代工程证据。

## 研究止损

本轮研究先确定交付物和时间预算，优先查会改变选型的未知。新资料已不影响决策、剩余问题只能靠小样回答时，交付当前证据、限制与验证任务，转入制作。

停止发散不意味着伪称完成阅读。说明实际核查覆盖和待补项；用户已定案时不重新海选，只有新证据会实质推翻需求或可行性时才提出调整。

## 交付与贡献

完整核心通常包含目标引擎最终效果、相关应用视角、必要输入/参数变化、技术问题与方案、限制、来源和个人贡献。美术说明交代主形、节奏、空间关系和材质，而非只列节点。

维护贡献表：原课程/外部资产、既有个人扩展、本次新增、各自已验证与未验证内容。新增链不能继承旧工具的成熟度，也不能因此抹掉旧成果。

效率或性能提升须给条件、基线、指标与画面代价；未测只写目标或假设。分别验收成品画面、技术贡献与交付完整性，不能用参考质量或方案评分代替本人完成度。
